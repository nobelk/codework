# Independent review

Use a separate read-only subagent when the host and session permit delegation. Otherwise hand the packet to a different model in a separate read-only session. Include absolute artifact paths, the exact file hashes or Git revision under review, repository rules, source inputs, confirmed decisions, the focus below, and the check results. Ask for numbered findings citing a file and section or line, the consequence, and a suggested change. Keep edits and decisions in the calling session.

If neither review route is available, give the user the packet and mark independent review pending. If a report makes claims without showing which artifact it read, request a review with citations. Record the reviewer, revision, and findings or pending status. Recheck revised artifacts before reporting their status.

## Review focus

Review the software design document at <absolute document path>. The review context may list this file as skipped because of its size; open it at that path and read it in full before reviewing. Also read README.md, AGENTS.md, GEMINI.md, and repository guidance, anything under specs/, and the source code wherever the document describes existing behaviour. Review only this document; ignore other working-tree changes. Look for: statements that contradict the requirements or the code; contradictions between sections; elements or relationships that appear in a diagram but not in its table or in the interface section, and the reverse; misuse of the C4 model (a diagram that mixes levels, an element without a type or technology, an unlabelled relationship, a container that is really a component); an architecture pattern that the stated drivers do not justify, or that the diagrams do not actually follow; entities with no owning container, and wrong keys or cardinalities; interfaces missing a protocol, a format, authentication, or failure behaviour; components with an unclear responsibility or a circular dependency; user tasks the interface design does not cover; assumptions the design depends on but does not state, and dependencies without a version or an owner; terms used but not in the glossary, or used with two meanings; vague, unverifiable, or promotional wording; and Mermaid syntax that would not render. For each finding, output a numbered item with the section, the issue, and the suggested change. Output findings only; do not rewrite the document. Verify the PRD requirement IDs, ADR links, and task handoff.
